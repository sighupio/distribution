# SIGHUP Distribution Release v1.36.0

Welcome to SD release `v1.36.0`.

The distribution is maintained with ❤️ by the team [SIGHUP by ReeVo](https://sighup.io/).

This version adds support for Kubernetes 1.36, updates all core modules, and introduces the new `utilities` core module, with Headlamp as its first package, for the `OnPremises` and `Immutable` kinds.

## New features 🌟

- [[#575](https://github.com/sighupio/furyctl/issues/575)] OnPremises and Immutable: add support for the new [`furyctl renew kubeconfigs`](https://github.com/sighupio/distribution/pull/588) command. It renews the kubeconfig file of the admin and the kubeconfig files of the users in `spec.kubernetes.advanced.users.names`. Then it downloads them to the working directory. A user that you add to the configuration file gets a kubeconfig file. It is not necessary to apply the kubernetes phase.
- [[#600](https://github.com/sighupio/distribution/pull/600)] Immutable: `spec.infrastructure.proxy` now applies to the whole node and not only to containerd. kubelet, etcd, the system extension downloads and command line tools like `curl` now use the proxy. Note that proxy configuration does not apply to the operating system installation step.
- [[#601](https://github.com/sighupio/distribution/pull/601)] Immutable: the infrastructure phase now upgrades the load balancers. The new `upgrade-load-balancers.yml` playbook updates the operating system, the system extensions and the configuration. It upgrades one load balancer at a time, so the virtual IP address stays available. The playbook stops before it changes anything when a load balancer does not answer.
- [[#612](https://github.com/sighupio/distribution/pull/612)] Adds `module-utilities` with Headlamp as its first package, for OnPremises and Immutable. Headlamp is exposed at `dashboard.<baseDomain>`. Set `spec.distribution.modules.utilities.headlamp.type` to `token-auth` or `sso` to install it. With `token-auth`, the users log in with their own Kubernetes token and get the permissions of that token. Set the optional `clusterRole` field to also bind a ClusterRole to the `headlamp` ServiceAccount, so that its token can be used to log in. With `sso`, Headlamp is behind Pomerium, and the group in `oidcGroup` gets read-only access to the cluster. With `sso`, the API server also accepts the `pomerium` audience in the OIDC tokens, unless it is already the `client_id` in `spec.kubernetes.advanced.oidc`.
- [[#618](https://github.com/sighupio/distribution/pull/618)] Immutable: the upgrade now updates Flatcar on each node to the exact version that the release pins. The installer downloads the update payload, compares its SHA-256 checksum, and installs it with `flatcar-update` before it drains the node. Thus a missing or bad payload stops the upgrade while the node still serves. The nodes no longer ask an update server. Automatic OS updates stay off with `SERVER=disabled` in `/etc/flatcar/update.conf`, as the Flatcar documentation recommends, and update-engine is no longer masked. With `spec.infrastructure.proxy`, update-engine does not use the proxy.

## Bug Fixes 🐛

- [[#626](https://github.com/sighupio/distribution/pull/626)] Immutable: a node reports `booted` to furyctl only after sshd listens. Before this release, the report could come some seconds before port 22 listened, and the first Ansible play of the apply could fail to connect to the node.
- [[#581](https://github.com/sighupio/distribution/issues/581)] Immutable: node `storage.installDisk` now accepts persistent device paths like `/dev/disk/by-id/wwn-...`, `/dev/disk/by-path/...` and `/dev/mapper/...`. The field is validated the same way Butane/Ignition validates its own device fields — the path must be absolute and clean — instead of the previous alphanumeric-only pattern that rejected every `/dev/disk/by-*` symlink.
- [[#603](https://github.com/sighupio/distribution/pull/603)] Immutable: the preflight check now stops when it cannot reach a control plane node. Before this release, a node that did not answer gave the same result as a cluster that does not exist. The apply then continued as if the cluster was new. The check also finds an existing cluster when a control plane node other than the first one holds the admin kubeconfig.
- [[#605](https://github.com/sighupio/distribution/pull/605)] Immutable: the preflight check now reads every host, and not only the control plane hosts. It tells a cluster whose control plane does not answer from a cluster that does not exist, and furyctl stops the apply in the first case.
- [[#577](https://github.com/sighupio/distribution/pull/577)] Makes the admin.conf fetch in fetch-admin-conf-playbook.yaml pick the right master, and stops the playbook from failing on purpose to signal "cluster doesn't exist".
- [[#573](https://github.com/sighupio/distribution/issues/573)] Immutable: you can now apply the configuration file that `furyctl create config` generates without changes to it. Each node must now declare `arch`, and the generated file sets it on all the nodes. The schema declared a default of `x86-64` for `arch`, but nothing applied that default. A node without the field made `furyctl apply` stop with a template error.
- [[#607](https://github.com/sighupio/distribution/pull/607)] DR module: fix velero triggering immediate backups after every `furyctl apply`.
- [[#597](https://github.com/sighupio/distribution/issues/597)] OnPremises and Immutable: the API server now uses the OIDC groups prefix from the configuration file. Before this release, the installers ignored `spec.kubernetes.advanced.oidc.group_prefix` and always used `oidc:`. The new field is `groups_prefix`, the same name as `claimMappings.groups.prefix` in the API server `AuthenticationConfiguration`. `group_prefix` is deprecated, but it still works when `groups_prefix` is not set. Refer to the Breaking Changes section.
- [[#589](https://github.com/sighupio/distribution/issues/589)] All kinds: the schema now validates the `storageSize` fields of Prometheus, OpenSearch and MinIO as Kubernetes quantities, for example `10Gi`. A value like `10GB` now fails when furyctl validates the configuration, and not during the apply. The `retentionSize` field of Prometheus does not change, because it uses Prometheus units like `120GB`.

## Breaking changes 💔

- [[#600](https://github.com/sighupio/distribution/pull/600)] Immutable: `spec.infrastructure.proxy` now applies to every service on the node, so `noProxy` must list the addresses that the cluster uses to reach itself. Add the network of the nodes, the control plane address, the pod CIDR and the service CIDR. If these addresses are absent, kubelet and the other components try to reach the API server through the proxy, and the cluster does not start.
- [[#597](https://github.com/sighupio/distribution/issues/597)] OnPremises and Immutable: if you set `spec.kubernetes.advanced.oidc.group_prefix` to a value that is not `oidc:`, the OIDC group names change when you apply. Before this release, the API server always used `oidc:`, so your `RoleBinding` and `ClusterRoleBinding` objects probably use `oidc:`. Update these bindings to the prefix that you set before you apply, or the users of these groups lose access. If you did not set the field, or you set it to `oidc:`, nothing changes.
- Tracing: Tempo no longer supports the OpenCensus receiver.

## Known issues ⚠️

- OnPremises and Immutable with Cilium: Cilium 1.18 and 1.19 have a bug ([cilium/cilium#44891](https://github.com/cilium/cilium/issues/44891)). When the upgrade replaces a Cilium pod that is not Ready, the `hubble-relay` pod on that node can stay not Ready, and `furyctl apply` waits on `deployment/hubble-relay`. The Immutable upgrade now waits until the pods of each node are Ready, unless you use `--force pods-running-check`.

  Before you upgrade, make sure that all the Cilium pods are Ready:

  ```bash
  kubectl -n kube-system rollout status ds/cilium
  ```

  If the fault occurs, drain the node of the `hubble-relay` pod, reboot it, then uncordon it. A restart of the Cilium pod does not clear the fault.
